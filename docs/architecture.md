# SCI-Skills 架构

## 运行边界

SCI-Skills 使用“一个总控、十三个独立专家”的结构。

- `sci-skills`：识别论文路线、诊断阶段、选择专家、核验专家返回、决定通过或修复。
- `sci-skills-*`：完成边界明确的专业任务，不独立宣布论文阶段通过。
- 专家直接调用：允许生成临时或局部产物，但阶段状态仍由总控复核。

## 当前协作逻辑

3.0.2 保留 3.0.1 的协作方式：总控从当前阶段候选专家中选择最小必要组合，默认不超过两位主要专家；专家之间的新增动态协作机制留待后续版本。

## 为什么运行目录保持平铺

部分 Skill 发现机制只检查指定目录的直接子目录。为降低漏识别风险，14 个 Skill 都直接放在 `skills/` 下，各自根目录直接包含 `SKILL.md`。

“文献与证据、分析与绘图、写作与表达、审查与投稿”仅是面向用户的产品分类，记录在 README 和 `suite.yaml` 中，不改变运行路径。

## 独立性原则

每个专家继续保留自身所需的 `SKILL.md`、`agents/openai.yaml`、引用、模板、结构定义、脚本与资源。即使存在少量公共规则副本，也不把它们改成必须依赖套件根目录的共享运行文件，以免单独安装专家后失效。
